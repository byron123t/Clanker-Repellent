# Synthetic sample records

All data in this directory is generated by `../build_fixtures.py`. Project names, paths,
timestamps, file contents, and response bodies are authored examples. The generator builds
bytes in memory and writes these two files; it does not scan or modify a software project:

- `journal.json`: record summaries, file inventories, edit positions, and response metadata.
- `objects.json`: saved example bytes, base64 encoded and indexed by their SHA-256 hashes.

Run `python3 build_fixtures.py` from the template directory to regenerate them. Restart the
sample server afterward. Keep `README.md` when replacing generated files.

## Design scenarios

| Project | What to exercise |
| --- | --- |
| `native-util` | Partial file coverage and a binary snapshot preview |
| `web-client` | A larger JavaScript file inventory |
| `wasm-runtime` | A few WebAssembly files and binary/base64 previews |
| `markdown-core` | TypeScript labels and a smaller inventory |
| `docs-site` | A 280-file inventory and a restored historical record |
| `legacy-import` | An unknown coverage denominator |
| `build-staging` | A pending snapshot with no snippet placements |

File kinds provide the same display categories as the real API. Sample source files use
simple declarations and project-note comments. WASM examples use a minimal module and a
custom data section. Binary snapshots use a short byte sequence. These are preview fixtures;
they make no claim about compilation, runtime behavior, or retention in a real build.

The generator constructs each original version, added snippet, and updated version together.
Their lengths, hashes, edit offsets, and spans are consistent, so charts and exact-byte
downloads can be checked. Example notes describe ordinary project conventions.

The three response records contain generated HTML, JavaScript, and WASM bodies. They have
fictional request paths and are not captures of network traffic. Updated samples use valid
format-specific data or comments. `examples` is empty for every project because there is
no underlying project on which to run commands.

The summary includes `template: true`. Keep that marker and show **Synthetic sample data**
in the interface. The fixtures are independent of any live journal or other repository.
